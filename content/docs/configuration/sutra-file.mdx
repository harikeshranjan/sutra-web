# .sutra File

The .sutra configuration file defines repository metadata, commit styling rules, and analysis behavior for the Sutra AI-powered commit assistant.
It enables structured commit message generation and configurable repository analysis by specifying style preferences and processing options.

## Overview

The configuration file follows a structured format divided into the following sections:
- Repository Settings
- Style Configuration
- Analysis Configuration

Example:

```bash
REPOSITORY_URL = https://github.com/Harikesh-14/Sutra.git
BRANCH_NAME = main

[STYLE]
USES_CONVENTIONAL = true
TONE = imperative
DETAIL_LEVEL = moderate

[ANALYSIS]
ENABLE_PROGRESS_ANALYSIS = true
CACHE_ANALYSIS = false
```

## 1. Repository Configuration

Defines which repository and branch Sutra operates on.

`REPOSITORY_URL`

Type: string
Required: Yes

Specifies the Git repository URL used for commit analysis and generation.

Example:

```bash
REPOSITORY_URL = https://github.com/Harikesh-14/Sutra.git
```

Sutra uses this value to:
- Fetch commit history
- Analyze repository changes
- Generate context-aware commit messages

`BRANCH_NAME`

Type: string
Required: Yes

Specifies the branch Sutra should analyze and generate commits against.

Example:
```bash
BRANCH_NAME = main
```

This ensures:
- Commit history is read from the correct branch
- Analysis is scoped properly
- Progress tracking remains consistent

## 2. Style Configuration ([STYLE])

Controls how AI-generated commit messages are formatted.

```bash
[STYLE]
USES_CONVENTIONAL = true
TONE = imperative
DETAIL_LEVEL = moderate
```

These settings directly influence the structure and tone of the generated commit messages.

`USES_CONVENTIONAL`

Type: boolean
Default: true (recommended)

Determines whether commit messages follow the Conventional Commits specification.

When enabled, commit messages follow this structure:

```bash 
<type>(optional-scope): <message>
```

### Recommendation

`imperative` is strongly recommended and aligns with Git best practices:

> "Use the imperative mood in the subject line"

Example:

```bash
fix(api): resolve null pointer error
```

`DETAIL_LEVEL`

Type: `"low" | "moderate" | "high"`
Required: Yes

Determines how descriptive the commit message should be.

### Options

`low`
Short, concise message.

```bash
fix: handle login bug
```

`moderate`
Balanced clarity and brevity (recommended).

```bash
fix(auth): handle login failure when token is expired
```

`high`
Highly descriptive message with detailed context.

```bash
fix(auth): handle login failure when JWT token is expired and improve error response formatting
```

## 3. Analysis Configuration ([ANALYSIS])

Controls repository inspection and performance behavior.

```bash
[ANALYSIS]
ENABLE_PROGRESS_ANALYSIS = true
CACHE_ANALYSIS = false
```

`ENABLE_PROGRESS_ANALYSIS`
Type: boolean
Default: true

Enables commit history and repository progress tracking.

When enabled, Sutra:

- Analyzes commit history
- Detects feature evolution
- Identifies refactoring trends
- Understands development velocity
- Generates context-aware commit suggestions

If disabled:
- Commit generation becomes change-based only
- No historical context is used

`CACHE_ANALYSIS`
Type: boolean
Default: false

Determines whether repository analysis results are cached.

### When `true`
- Improves performance
- Reduces repeated repository scans
- Useful for large repositories

### When `false`
- Forces fresh analysis every run
- Ensures up-to-date commit context
- Slightly slower but more accurate

### Recommended setting:
- `true` for large teams or CI environments
- `false` during active development
